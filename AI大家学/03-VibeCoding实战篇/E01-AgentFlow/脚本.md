## 【第一部分：为什么要做这个项目】（0:40-2:30）

（画面：配音+PPT风格动画）

先说为什么选这个项目。

2026年，AI Agent平台已经不是一个新概念了。Dify、Coze、FastGPT——市面上不缺产品。但问题来了：

**第一，它们都是SaaS。** 你的数据、你的对话、你的知识库，全在别人服务器上。对于很多企业来说，这是不可接受的。

**第二，你用了但你不理解它。** 你知道Agent是怎么运转的吗？工作流引擎是怎么跑的？MCP是怎么接入的？用了半年Dify，你可能还是说不清楚。

**第三，也是最重要的——VibeCoding时代，这种项目是最好的练手对象。**

（画面：VibeCoding定义动画）

什么是VibeCoding？简单说就是：**你不用写代码，你用自然语言描述需求，AI帮你把代码写出来。**

但VibeCoding不等于"随便说两句AI就能搞定一切"。这里面有一个核心的思维转变——

（画面：大字+强调动画）

> **你不再是程序员，你是架构师。Claude Code是你的工程团队。**

你负责想清楚做什么、不做什么、做到什么标准。它负责执行。你想得越清楚，它做得越准确。你越模糊，它越跑偏。

这句话不是鸡汤，是我踩了坑之后总结的。后面你会看到。

## 【第二部分：AgentFlow到底做什么】（2:30-5:00）

（画面：切换到屏幕录制 / 或架构图动画）

好，那我们到底要做一个什么东西？

一句话：**一个可以本地部署的AI Agent开发平台。**

具体来说，它要支持这些核心功能：

（画面：功能全景图，逐个模块亮起）

| 模块 | 功能 | 说明 |
|------|------|------|
| **模型管理** | 多模型提供商接入 | 支持OpenAI、Claude、DeepSeek等，可以切换、测试连通性 |
| **Agent管理** | 创建和配置Agent | 设置Agent的名称、描述、System Prompt、关联模型和工具 |
| **对话引擎** | 流式对话交互 | 支持多轮对话、流式输出、对话历史 |
| **RAG知识库** | 文档上传和检索 | 上传文档 → 切片 → Embedding → 向量存储 → 对话时自动检索 |
| **工作流编排** | 可视化流程设计 | 拖拽式设计工作流，执行引擎让流程跑起来 |
| **MCP工具** | 标准化工具接入 | 接入MCP Server，让Agent能调用外部工具 |

（画面：AgentFlow架构图）

技术选型：

- **后端**：Spring Boot（Java）—— 稳定、生态成熟、Claude Code写得不错
- **前端**：Vue 3 + Element Plus —— 组件丰富、Claude Code也写得不错
- **数据库**：PostgreSQL + pgvector（向量存储直接用PG扩展，不引入额外组件）
- **架构**：模块化单体 —— 不是微服务！一个应用内模块化拆分，够用

（画面：强调"模块化单体"vs"微服务"的对比动画）

这里要特别说一下架构选择。很多人一上来就想搞微服务——服务注册、配置中心、链路追踪……这些对于AgentFlow来说完全没必要。我们是一个**本地部署、单人或小团队使用**的平台，模块化单体架构完全够用。

**这就是"做什么"和"不做什么"的第一个例子。** 微服务是"不做什么"——至少现在不做。

## 【第三部分：第一天踩的坑——不要急着让AI写代码】（5:00-8:30）

（画面：屏幕录制——打开Claude Code，开始操作）

好，接下来我要展示一个非常重要的环节：**我第一天是怎么踩坑的，以及正确的做法是什么。**

（画面：打字效果模拟）

第一天，我很兴奋，直接告诉Claude Code：

> "帮我设计一个AI Agent开发平台的后端架构，支持多模型、多Agent、工具调用。"

（画面：Claude Code快速输出一大段架构设计文档——看起来很专业）

它给了我一个方案。微服务划分清晰，技术选型合理，甚至画了架构图。看起来非常专业。

但我越看越不对：

（画面：逐项标注问题，红色高亮）

- ❌ 引入了服务注册中心（Nacos）—— 我只是本地用，不需要
- ❌ 引入了分布式配置中心 —— 单体应用不需要
- ❌ 引入了链路追踪（SkyWalking）—— 过度设计
- ❌ 引入了消息队列（RocketMQ）—— 根本没有高并发场景

**它给的方案像是要做一个服务百万用户的生产系统，而我只需要一个本地可运行的平台。**

问题出在哪？

（画面：大字动画，三个"没有"依次出现）

> 1. 我**没有**定义产品边界：什么做、什么不做
> 2. 我**没有**明确架构约束：这是单人项目，不是团队项目
> 3. 我**没有**给它任何规范：命名、接口设计、错误处理

**Claude Code不是不能做好，是我没告诉它"好"的标准是什么。**

---

（画面：切换到正确做法的演示）

所以我停下来，花了整整一个晚上做三件事：

### 第一件事：产品边界定义

（画面：展示一页纸的产品定义文档）

用"三问裁剪法"：
1. **做什么？** —— 上面列出的6个核心模块
2. **不做什么？** —— 不做微服务、不做多租户、不做用户权限管理、不做商业化功能
3. **做到什么程度？** —— 本地可运行、单用户使用、功能链路完整

把这一页纸喂给Claude Code，它的输出质量立刻不一样了。

### 第二件事：核心数据模型

（画面：ER图动画展示）

五六张核心表：

```
model_provider    — 模型提供商（名称、类型、API地址、密钥）
agent_config      — Agent配置（名称、描述、System Prompt、关联模型）
conversation      — 对话会话（Agent关联、创建时间）
message           — 对话消息（会话关联、角色、内容、时间戳）
knowledge_base    — 知识库（名称、描述）
document          — 文档（知识库关联、文件路径、切片状态）
```

不需要一步到位把所有表都想清楚，但核心实体之间的关系必须先定义。这是系统的骨架。

### 第三件事：CLAUDE.md

（画面：展示CLAUDE.md文件内容，关键部分高亮）

这是最关键的一步。**CLAUDE.md是Claude Code的"项目手册"**，放在项目根目录，Claude Code每次启动都会读它。

里面写什么？

```markdown
# AgentFlow 项目规范

## 项目简介
AI Agent开发平台，模块化单体架构，Spring Boot + Vue 3

## 架构约束
- 单体应用，不做微服务
- 数据库使用PostgreSQL + pgvector
- 不引入消息队列、服务注册等中间件

## 代码规范
- 后端包名：com.agentflow
- Controller层只做参数校验和转发
- Service层包含业务逻辑
- 统一返回格式：Result<T>
- 异常处理：自定义ErrorCode枚举

## 当前阶段
工程搭建阶段，先完成后端骨架和前端初始化
```

（画面：标注"这份文件是后续所有开发的基础"）

**有了这三样东西——产品边界、数据模型、CLAUDE.md——第二天一切都变了。**

我给Claude Code的不再是模糊的大需求，而是清晰的小任务。比如：

> "按照CLAUDE.md中的接口规范，实现模型提供商的CRUD接口，包含连通性测试功能，异常按ErrorCode枚举区分。"

它的输出质量发生了质的飞跃。**不是因为它变聪明了，是因为我给它的输入变清晰了。**

### Step 1：创建项目（8:30-10:00）

（屏幕录制）

打开Claude Code，初始化项目：

> "创建一个Spring Boot 3项目，包名com.agentflow，Java 17，包含以下依赖：Spring Web、Spring Data JPA、PostgreSQL Driver、Lombok。同时创建Vue 3前端项目，使用Vite + Element Plus。"

（画面：Claude Code快速生成项目结构，加速播放）

看一下生成的目录结构：

```
agentflow/
├── backend/
│   ├── src/main/java/com/agentflow/
│   │   ├── config/          # 配置类
│   │   ├── controller/      # 接口层
│   │   ├── service/         # 业务层
│   │   ├── repository/      # 数据访问层
│   │   ├── model/           # 数据模型
│   │   │   ├── entity/      # JPA实体
│   │   │   ├── dto/         # 传输对象
│   │   │   └── enums/       # 枚举
│   │   ├── common/          # 公共组件
│   │   │   ├── Result.java  # 统一返回
│   │   │   └── ErrorCode.java # 错误码
│   │   └── AgentFlowApplication.java
│   ├── src/main/resources/
│   │   └── application.yml
│   └── CLAUDE.md             # 项目规范
├── frontend/
│   ├── src/
│   │   ├── views/
│   │   ├── components/
│   │   ├── api/
│   │   └── App.vue
│   └── package.json
└── docker-compose.yml        # 一键启动
```

### Step 2：写入CLAUDE.md（10:00-11:00）

（屏幕录制）

把刚才准备好的项目规范写入CLAUDE.md：

> "在项目根目录创建CLAUDE.md，内容如下……"

（画面：展示完整的CLAUDE.md写入过程）

### Step 3：核心数据模型（11:00-12:30）

（屏幕录制）

> "按照以下ER关系，生成JPA实体类：
> - ModelProvider：id, name, type(枚举：OPENAI/ANTHROPIC/DEEPSEEK), apiUrl, apiKey, status
> - AgentConfig：id, name, description, systemPrompt, modelProviderId, temperature, maxTokens
> - Conversation：id, agentConfigId, title, createdAt
> - Message：id, conversationId, role(枚举：USER/ASSISTANT/SYSTEM), content, createdAt
> 
> 使用Lombok注解，JPA注解，字段命名遵循CLAUDE.md中的规范。"

（画面：Claude Code生成实体类代码，加速播放。关键代码片段停留展示）

**跑起来了。**

这就是第一期的全部成果：项目骨架搭建完成，核心数据模型定义好了，CLAUDE.md写好了，一键可以启动。
